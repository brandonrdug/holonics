# The founding plan for the live standing.
#
# Read by `soma/tools/standing-deposit`. Every path is relative to the repository root; the tool
# refuses an absolute path, a `..` component, or whitespace, because a deposit that folded a
# checkout location into its lineage would drift the moment the tree moved and the drift would be
# indistinguishable from corruption (`CLAUDE.md` §0).
#
# What is deposited here is the Lean the machine generated and the exterior kernel graded. It was
# written into `/output/`, which `.gitignore` ignores. That is the exact mechanism that lost the
# laboratory's tiger phase-atlas figures and `semantics_invariant_under_exact_chart.lean`
# permanently — only a name, a proof term and a SHA-256 of that theorem survive, at no commit in
# either repository.
#
# `mount` declares the closure material, and ORDER IS LOAD-BEARING: the closure hash folds each
# mount's content digest in the order written. The executable is deliberately absent from these
# foundings. A `cargo` example binary is not reproducible from tracked material alone — it carries
# the toolchain, the resolved lock, and the profile — so recording its hash would report closure
# drift on every rebuild and say nothing about whether the machine advanced. What is recorded
# instead is the source that founds the return. The consequence is stated rather than hidden: a
# toolchain change is NOT visible in these closures. Add an `executable` line to a founding whose
# binary is itself deposited and it will be.
