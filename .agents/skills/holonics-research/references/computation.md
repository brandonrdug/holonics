Recover `docs/DEVELOPMENT.md` and the current interface/owner for the requested operation.
Prediction release is the generated output. A later comparison, retained handle or successor
publication has its own contract; none is an extra faculty that turns a face into output.
Use source/condition equations, generator composition and retained statistics to specify work.

Before adding machinery to a slow campaign, inspect one actual operation and its causal work:
whole-prefix reevaluation, dense expansion, repeated allocation/transfer, growing replay,
incorrect source contact, or a missing supported primitive require different repairs. Choose
a representation from the consuming equation. Do not declare history mathematically necessary
merely because the current implementation rereads it.

Use the available native owner; shared immutable standing and owned differences preserve
continuity. Caller-chosen experimental apertures remain visible. Resource pressure calls for
factorization, placement or an explicit resource result, not an invented semantic capacity.

Measure through `docs/DEVELOPMENT.md#performance-and-information-measurements`. Keep operation
count and elapsed interval from the same population. Separate setup/first-use, repeated calls,
readout and full delivery. Inspect exact returned values before lossy conversion; integer
truncation is not a rational equality test. Match displayed rates and quantiles to retained
raw samples. CPU/GPU/process/payload memory and code/physical units are different receivers.

Floating-point observer statistics, scalar objectives and explicit resource policies are
legitimate at their declared scope; native exactness does not ban them. A timeout is an
unfinished run, not mathematical infeasibility. A useful inferred generator or mathematical
output is reported for its own consequence and costs, without a vague intelligence qualifier.

When the user asks for a simple bounded edit, make it and run its relevant check. This route
does not require archive archaeology, a benchmark campaign or a new research record for an
ordinary low-impact change. Use broader recovery when the requested relation or failure needs it.
