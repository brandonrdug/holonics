## The operator's request and return

[definition] A request specifies a mathematical operation or constraint, its domain, supplied
source material, available ports and desired receiver. Where needed it also specifies a
time/index interval, precision and resource aperture. These are legitimate task conditions,
like selecting an operation on a calculator. A task name is not an interior semantic identity
or a substitute for the actual constraints.

[definition] A return can contain an exact value, an enclosure, a family of solutions, an
executable generator or a separating obstruction. State which was returned, its domain and
what was actually checked. A found representation also carries its decoder, source/clock
relation, retained alternatives and declared costs. Exhausting a finite grammar and exhausting
all mathematical possibilities are different results. Interrupted construction retains its
frontier and work; it does not report a false impossibility.

[definition] Present the requested expression/object, returned value or algorithm, applicable
conditions and an explanatory comparison. For a nonunique result, expose the family and the
distinction a further observation would resolve. For a failed construction, show the actual
incompatible equation or missing representation. Internal allocation handles and proof-assistant
plumbing do not belong in the operator's flow. No new UI or command interface is claimed here.

## One construction, two application receivers

[proved-derived] Let p=ac, q=bd and r=(a+b)(c+d). The same internal products support:

| Requested application | Returned face |
|---|---|
| Multiply a+ib and c+id | `(p−q, r−p−q)` |
| Multiply polynomials a+bx and c+dx | Coefficients `(p, r−p−q, q)` |

Expansion gives both identities over their respective commutative scalar charts. The first
receiver is already returned by the exact search. Both now execute through one retained product core: the changed output map is solved through
the existing preimage owner and applied to the same resident product. A third receiver can request just the cross coefficient ad+bc. This tests shared
construction and receiver-specific work while preserving the distinct application occurrences.

[definition] The use retains the original factor/source occurrence, new receiver and each
application's current. If the full product tuple is retained, it can serve the second receiver.
If only the two-coordinate complex output was retained, the three polynomial coefficients
need not be recoverable. Compute that preimage/obstruction instead of assuming a source. This
tests whether the workshop retained the right interior for its next task.

[counterexample] The inputs `(a,b,c,d)=(1,0,1,0)` and `(0,1,0,−1)` both produce the complex
face `(1,0)`. Their polynomial coefficient faces are respectively `(1,0,0)` and `(0,0,−1)`.
The lost distinction cannot be recovered from that complex output alone. Keeping the relevant
product tuple or an equivalent family representation makes the requested receiver possible.
