# SolveSpace: data types and solving machinery

Source read: `refs/solvespace` at commit `3297d9a38f28` (2026-07-27), shallow clone of
`github.com/solvespace/solvespace`. All paths below are relative to that checkout.

## 1. Identity and purpose

SolveSpace (Jonathan Westhues, 2008–2013; community-maintained since) is a parametric 2D/3D CAD
program built around a geometric constraint solver. The user creates *requests* (line, circle, arc,
cubic, workplane, datum point, text, image) inside ordered *groups*; requests expand into *entities*
whose *params* are unknowns; *constraints* generate *equations* over params; a Newton/least-squares
solver over a symbolically assembled Jacobian solves each group in order. Downstream groups (extrude,
lathe, revolve, helix, step-and-repeat, link/assemble) build NURBS shells (`src/srf/`) and triangle
meshes (`src/mesh.cpp`) with booleans. The kernel is also the C library `libslvs` (`include/slvs.h`,
`src/slvs/lib.cpp`); the model persists as a flat key=value text file (`.slvs`).

## 2. Core data types (`src/sketch.h`, `src/param.h`, `src/expr.h`, `src/solvespace.h`)

**Handles.** Every object is addressed by a 32-bit handle; the bit layout encodes lineage
(`src/sketch.h:75-115, 940-979`):

```cpp
class hGroup   { // bits 15: 0 -- group index
class hRequest { // bits 15: 0 -- request index
class hEntity  { // bits 15: 0 -- entity index   31:16 -- request index
class hParam   { // bits 15: 0 -- param index    31:16 -- request index   (src/param.h)
inline hEntity hGroup::entity(int i) const   { r.v = 0x80000000 | (v << 16) | (uint32_t)i; }
inline hParam  hGroup::param(int i) const    { r.v = 0x80000000 | (v << 16) | (uint32_t)i; }
inline hEntity hRequest::entity(int i) const { r.v = (v << 16) | (uint32_t)i; }
inline hParam  hRequest::param(int i) const  { r.v = (v << 16) | (uint32_t)i; }
inline bool hEntity::isFromRequest() const   { if(v & 0x80000000) return false; else return true; }
inline hGroup hEntity::group() const         { r.v = (v >> 16) & 0x3fff; }
inline hEquation hConstraint::equation(int i) const { r.v = (v << 16) | (uint32_t)i; }
inline hParam    hConstraint::param(int i) const    { r.v = v | 0x40000000 | (uint32_t)i; }
inline hEquation hEntity::equation(int i) const     { r.v = v | 0x40000000 | (uint32_t)i; }
inline bool hEquation::isFromConstraint() const     { if(v & 0xc0000000) return false; else return true; }
```

So `0x00040010` is param 16 of request 4; `0x80020000` is entity 0 generated by group 2; and an
equation handle without bits 30/31 set maps back to its constraint via `hEquation::constraint()`
(`v >> 16`). `IdList<T,H>::AddAndAssignId` (`src/dsc.h:456`) allocates `MaximumId()+1`.

**Param** (`src/param.h`): `{ int tag; hParam h; double val; bool known; bool free; Param *substd; }`.
`known` means "already solved by an earlier group"; `free` is set by the DOF test; `tag` is the
solver's subsystem label.

**Expr** (`src/expr.h:23-52`): a tree with `Op op; Expr *a; union { double v; hParam parh; Param *parp; Expr *b; }`:


`ReferencedParams` (returns `NO_PARAMS`/`MULTIPLE_PARAMS`/the single param), `DeepCopyWithParamsAsPointers`.
`ExprVector {x,y,z}` and `ExprQuaternion {w,vx,vy,vz}` (with `RotationU/V/N`, `Rotate`, `Times`,

## 3. Solving machinery

**Request expansion** (`src/request.cpp:84-198`). A table `EntReqMap` gives each request type its
entity type, point count, and whether it has a normal and a distance (e.g. `CIRCLE: 1 pt, normal,
distance`; `ARC_OF_CIRCLE: 3 pts, normal`; `CUBIC: 4 + extraPoints`). `Request::Generate` emits the
main entity at `h.entity(0)`, points at `h.entity(i+1)` with params `h.param(16+3*i+{0,1,2})`
(2D points use only two: `POINT_IN_2D` with `param[0],param[1]` = u,v), the normal at `h.entity(32)`
(`NORMAL_IN_3D` with quaternion params `h.param(32..35)`, or `NORMAL_IN_2D` with no params because
it is "just a copy of the workplane quaternion"), and the distance at `h.entity(64)`/`h.param(64)`.

**Point evaluation and workplane projection** (`src/entity.cpp:509-660`):

```cpp
case Type::POINT_IN_2D: {
    EntityBase *c = SK.GetEntity(workplane);
    ExprVector u = c->Normal()->NormalExprsU();
    ExprVector v = c->Normal()->NormalExprsV();
    r = c->WorkplaneGetOffsetExprs();
    r = r.Plus(u.ScaledBy(Expr::From(param[0])));
    r = r.Plus(v.ScaledBy(Expr::From(param[1])));
```

`PointGetExprsInWorkplane(wrkpl,&u,&v)` returns the raw params when the point lives in that
workplane, otherwise projects the 3D expression: `ev = PointGetExprs() - wp; u = ev·wu; v = ev·wv`.
A workplane entity is `point[0]` (origin) + `normal` (quaternion); `WorkplaneGetPlaneExprs` gives
`n` and `d = p0·n`. Transformed points: `POINT_N_TRANS: numPoint + trans*timesApplied`;
`POINT_N_ROT_AA: q(theta*timesApplied, axis).Rotate(numPoint - offset) + offset`; etc.

**Constraint equations** (`src/constrainteq.cpp`). `ConstraintBase::Generate` (line 252) adds a
private param `valP = h.param(0)` only for `PT_ON_LINE`, `SAME_ORIENTATION`, and 3D `PARALLEL` /
`CUBIC_LINE_TANGENT` (the scalar multiplier in `VectorsParallel3d(a,b,p) = a - b*p`).
`GenerateEquations` is a switch producing one `Equation` per scalar; the `workplane` field selects
projected vs. true geometry and 2 vs. 3 equations:

```cpp
case Type::PT_PT_DISTANCE:
    AddEq(l, Distance(workplane, ptA, ptB)->Minus(exA), 0);
case Type::POINTS_COINCIDENT: ... if(workplane == FREE_IN_3D) { 3 eqs pa-pb } else { au-bu, av-bv }
case Type::HORIZONTAL/VERTICAL: AddEq(l, (type == HORIZONTAL) ? av->Minus(bv) : au->Minus(bu), 0);
case Type::PARALLEL (2D): Expr *eq = (a.x->Times(b.y))->Minus(a.y->Times(b.x));
case Type::ANGLE: c = DirectionCosine(workplane, ae, be); AddEq(l, (c->Minus(rc))->Times(mult), 0);
case Type::WHERE_DRAGGED: AddEq(l, ev.x->Minus(Expr::From(v.x)), 0); ...   // pins to current value
```

`Distance(wrkpl,a,b)` is `|ea-eb|` in 3D or `sqrt(du²+dv²)` projected. `ANGLE` multiplies by
`0.01/(1.00001-|cos|)` near 0°/180° "to avoid false detection of inconsistent systems". `reference`
constraints generate nothing (`if(reference && !forReference) return;`) and are instead updated by
`ModifyToSatisfy()` (`valA += eq.Eval()`). Entities also generate equations
(`src/entity.cpp:938`): `NORMAL_IN_3D` adds `|q| - 1 = 0`; `ARC_OF_CIRCLE` adds `|c-s| - |c-e| = 0`
unless a coincident constraint already closes the arc; text/image add the rectangle relations.
Groups add theirs (`src/group.cpp:804-862`): `LINKED` normalizes its quaternion; `ROTATE/REVOLVE/HELIX`
pin `param(0..2)` to `predef.origin` and `param(4..6)` to the unit axis (param 3, the angle, is free);
`EXTRUDE` forces the extrusion vector normal to `predef.entityB` (`u·e = 0, v·e = 0`); `TRANSLATE`
forces `trans·n = 0`.

**Group-sequential solve.** `SolveSpaceUI::GenerateAll` (`src/generate.cpp:160-390`) sorts
`SK.groupOrder` by `Group::order`, moves the old `SK.param` into `prev` ("Don't lose our numerical
guesses"), clears `SK.entity`, then per group: `Request::Generate`, `Constraint::Generate`,
`Group::Generate` into `SK`; copies `prev` values into new params as initial guesses; and for groups in
`[first,last]` calls `SolveGroupAndReport`. `Generate::DIRTY` solves from the first dirty group to the
active one; `UNTIL_ACTIVE` from 0 to the active index; `ALL` everything; `REGEN` nothing. Groups
outside the range keep old values and are marked `known`. `WriteEqSystemForGroup(hg)`
(`src/generate.cpp:512`) rebuilds `sys.param` from *only this group's* requests, constraints and
group; any param of an earlier group is absent from `sys.param`, so when
`WriteJacobian` deep-copies each equation with `DeepCopyWithParamsAsPointers(&param, &(SK.param))`
those references resolve to `SK.param` pointers and behave as constants. That is the entire mechanism
by which "earlier groups are fixed inputs to later ones". Derived entities additionally bake earlier
geometry numerically: `CopyEntity` sets `en.numPoint = ep->actPoint.ScaledBy(scale)` (`src/group.cpp:1120`).

**Dragging.** `MarkDraggedParams()` (`src/generate.cpp:436`) inserts the params of
`GW.pending.point(s)`, the pending circle's distance and the pending normal into `sys.dragged`
(a `ParamSet`). Dragging is *soft*: in `SolveLeastSquares` dragged columns get `scale[c] = 1/20.0`
so "this parameter doesn't need to be all that big to get a large effect" (the minimum-norm step then
moves them least), and in `SolveBySubstitution` a dragged param survives as the substitution target.
Hard locking is the `WHERE_DRAGGED` constraint. `Pending::DRAGGING_POINTS` in `src/mouse.cpp:331`
calls `UpdateDraggedPoint` then `SS.MarkGroupDirtyByEntity` which schedules `GenerateAll(DIRTY)`.

**System::Solve** (`src/system.cpp:490-596`), in order:

1. `WriteEquationsExceptFor(NO_CONSTRAINT, g)`: constraint, entity, group equations. With
   `g->allDimsReference` labelled constraints are `ModifyToSatisfy()`'d instead; with
   `g->relaxConstraints` only `POINTS_COINCIDENT` survive.
2. `SolveBySubstitution()`: any equation `PARAM - PARAM = 0` where both are solver params unifies
   the two (`VAR_SUBSTITUTED`, `EQ_SUBSTITUTED`), builds a `SubstitutionMap`, rewrites all equations.
3. Solve-alone pass: equations referencing exactly one untagged param (`ReferencedParams`) get
   their own tag and are Newton-solved individually ("can be a huge speedup").
4. `WriteJacobian(0)`: rows = remaining equations, columns = remaining params; each entry is the
   symbolic `f->PartialWrt(p)` after `FoldConstants`, stored in `Eigen::SparseMatrix<Expr*> mat.A.sym`;
   `mat.B.sym` holds the folded residual expressions. Fails with `TOO_MANY_UNKNOWNS` past 2048.
5. `TestRank(dof)`: `EvalJacobian()` numerically, `SparseQR<..., COLAMDOrdering>` rank;
   `*dof = mat.n - jacobianRank`; `rankOk = jacobianRank == mat.m`. Skipped if
   `suppressDofCalculation` or `allowRedundant`.
6. `NewtonSolve()`: up to 50 iterations of `J(x_n)(x_{n+1}-x_n) = -F(x_n)`; step from
   `SolveLeastSquares()`, which factors `Aᵀ` by sparse QR for the minimum-norm solution when
   `m <= n` (the comment explains why forming `A Aᵀ` squared the condition number and produced false
   "unsolvable" reports on large sketches) and falls back to normal equations when `m > n`.
   Converged when every `|B_i| <= CONVERGE_TOLERANCE = LENGTH_EPS/1e2`.
7. Post-solve `TestRank` again; if rank-deficient and `andFindBad`,
   `FindWhichToRemoveToFixJacobian` re-derives the system once per constraint with that constraint
   omitted (non-coincident first, then coincident) and records every constraint whose removal restores
   `rank == m` into `bad` (the "remove any one of these" list), under `g->solved.findToFixTimeout`.
   Otherwise `MarkParamsFree(andFindFree)`: tagging each param `VAR_DOF_TEST` (dropping its column)
   and re-ranking; if rank is unchanged the param is `free` (drawn as an underconstrained point).
8. Write values back to `SK.param` (`known = true`, `free`), return `OKAY` or `REDUNDANT_OKAY`.
   On non-convergence, every equation with residual above tolerance whose handle
   `isFromConstraint()` contributes its constraint to `bad` (deduplicated by `tag`), returning
   `DIDNT_CONVERGE` / `REDUNDANT_DIDNT_CONVERGE`.

`Constraint::AddConstraint` (`src/constraint.cpp`) does `UndoRemember`, `AddAndAssignId`,
`Generate(&SK.param)`, `MarkGroupDirty`, and clears `dofCheckOk` so the next solve does a full rank
check (`forceDofCheck = !g->dofCheckOk`).

**Derived groups.** `Group::Generate` (`src/group.cpp:441-790`): `DRAWING_WORKPLANE` emits a
`NORMAL_N_COPY` (h.entity(1)), a `POINT_N_COPY` origin (h.entity(2)) and a `WORKPLANE` (h.entity(0))
computed numerically from `predef`; `EXTRUDE` adds params `h.param(0..2)` and, for each entity of
`opA`, `CopyEntity(..., REMAP_BOTTOM/REMAP_TOP, CopyAs::N_TRANS)` with `timesApplied` 0/2 (one-sided)
or -1/1 (two-sided); `TRANSLATE/ROTATE` loop `a = 0..valA-1` making copies with remap index `a`
(last is `REMAP_LAST`); `ROTATE` params are centre (0..2), angle (3), axis (4..6); `LINKED` copies
`impEntity` as `N_ROT_TRANS` with 7 transform params. `Group::Remap(in, copyNumber)` maps
`EntityKey{input, copyNumber}` to a fresh `EntityId` (persisted as `Group.remap`) and returns
`h.entity(id)`, so derived handles are stable across regeneration (limit 65535 per group).
`GenerateShellAndMesh` (`src/groupmesh.cpp:212`) builds `thisShell` from the source group's
`bezierLoops` and combines it with `RunningMeshGroup()->runningShell` via
`GenerateForBoolean(..., meshCombine)` (`MakeFromUnionOf/DifferenceOf/IntersectionOf/AssemblyOf`).
`SShell` = `IdList<SCurve>` + `IdList<SSurface>` (rational Bézier patches, `degm,degn <= 3`,
`ctrl[4][4]`, `weight[4][4]`, `List<STrimBy> trim`); booleans classify regions
`SURF_INSIDE/OUTSIDE/COINC_SAME/COINC_OPP` (`src/srf/surface.h`). `SMesh` is `List<STriangle>` with
BSP booleans (`src/polygon.h`).

## 4. File format and C API

`.slvs` (`src/file.cpp`). Header `VERSION_STRING "\261\262\263" "SolveSpaceREVa"`, then blank-line
separated records of `Key=value` lines, each closed by `AddGroup`, `AddParam`, `AddRequest`,
`AddEntity`, `AddConstraint`, `AddStyle`; then `Triangle`/`Surface`/`SCtrl`/`TrimBy`/`Curve` lines
for the last group's running mesh/shell. A single `SAVED[]` table
(`src/file.cpp:89-222`) drives both save and load (`{ 'c', "Constraint.valA", 'f', &(SS.sv.c.valA) }`;
types `x` hex, `d` int, `f` `%.20f`, `b` bool, `c` color, `S` string, `P` path, `M` remap map). Entities
are saved *with* `actPoint/actNormal/actDistance` so a linked file's geometry can be imported
numerically (`LoadEntitiesFromSlvs`) without re-solving. Minimal verbatim excerpt
(`test/request/datum_point/normal.slvs`, `test/constraint/pt_pt_distance/normal.slvs`):

Entity constants: `SLVS_E_POINT_IN_3D 50000, POINT_IN_2D 50001, NORMAL_IN_3D 60000, NORMAL_IN_2D 60001,
DISTANCE 70000, WORKPLANE 80000, LINE_SEGMENT 80001, CUBIC 80002, CIRCLE 80003, ARC_OF_CIRCLE 80004`;
`SLVS_FREE_IN_3D 0`. Constraint constants `SLVS_C_POINTS_COINCIDENT 100000` … `SLVS_C_ARC_LINE_DIFFERENCE 100037`
(same names as the internal enum, mapped in `src/slvs/lib.cpp:34-76`). Results:
`SLVS_RESULT_OKAY 0, INCONSISTENT 1, DIDNT_CONVERGE 2, TOO_MANY_UNKNOWNS 3, REDUNDANT_OKAY 4`.
`Slvs_Solve(sys, hg)` (`src/slvs/lib.cpp:1000`) loads every param into `SK.param` but only those with
`group == hg` into `SYS.param`, generates constraint params, calls `SYS.Solve(&g, &dof, &bad, calculateFaileds, false)`,
writes values back and fills `failed[]`. A newer stateful API (`Slvs_AddPoint2D`, `Slvs_AddLine2D`,
`Slvs_Distance`, `Slvs_MarkDragged`, `Slvs_SolveSketch(hg, &bad)`, `Slvs_ClearSketch`) wraps the same kernel.
Minimal C (adapted from `exposed/CDemo.c` `Example2d`):

```c
/* group 1 (fixed): workplane 200 = origin point 101 (params 1..3) + normal 102 (params 4..7) */

sys.entity[sys.entities++] = Slvs_MakeNormal3d(102, 1, 4, 5, 6, 7);
sys.entity[sys.entities++] = Slvs_MakeWorkplane(200, 1, 101, 102);
/* group 2 (solved): two 2d points with params 11..14 */
sys.param[sys.params++] = Slvs_MakeParam(11, 2, 10.0); sys.param[sys.params++] = Slvs_MakeParam(12, 2, 20.0);
sys.entity[sys.entities++] = Slvs_MakePoint2d(301, 2, 200, 11, 12);
sys.param[sys.params++] = Slvs_MakeParam(13, 2, 20.0); sys.param[sys.params++] = Slvs_MakeParam(14, 2, 10.0);
sys.entity[sys.entities++] = Slvs_MakePoint2d(302, 2, 200, 13, 14);
sys.constraint[sys.constraints++] = Slvs_MakeConstraint(1, 2, SLVS_C_PT_PT_DISTANCE, 200, 30.0, 301, 302, 0, 0);
sys.calculateFaileds = 1;
Slvs_Solve(&sys, 2);
if(sys.result == SLVS_RESULT_OKAY) printf("%d DOF\n", sys.dof);   /* prints 3 */
else for(i = 0; i < sys.faileds; i++) printf("bad constraint %d\n", sys.failed[i]);
```

## 6. Abstractions to lift for a Lean-based mathematics CAD

1. **Declarations vs. generated state.** `Sketch` splits `group/request/constraint/style` (editable)
   from `entity/param` (regenerated). Store only site/port/passage declarations; regenerate the site
   table and unknowns each time, reusing old values as initial guesses (`prev`).
2. **Lineage-bearing handles.** `hEntity = request<<16 | index`, `0x80000000` marks group-generated,
   `hParam = owner<<16 | slot`, `hEquation` recovers its constraint. A site id naming its passage makes
   orphan pruning a bit test and gives every residual a source for diagnostics.
3. **Fixed slot layout per owner.** Points at `param(16+3i)`, normal at `param(32..35)`, distance at
   `param(64)`: an owner's parameter space is a static schema independent of insertion order.
4. **Constraints are equation generators; the solver is type-blind.** `System` sees only
   `Equation{h, Expr*}`; the `workplane` field turns 3 scalar equations into 2. Ports/passages compile
   to residuals in a fixed grammar, so the solver never learns the geometry vocabulary.
5. **A closed symbolic algebra with exact derivatives.** `Expr::Op` has 15 constructors and
   `PartialWrt` is total; the Jacobian is assembled once as `SparseMatrix<Expr*>` and evaluated per
   iteration. Small enough to be a Lean inductive with a proven derivative: a verified Jacobian.
6. **Sequential groups: earlier layers are constants.** Only the active group's params enter
   `sys.param`; foreign references resolve to `SK.param` pointers; derived copies bake `actPoint`.
   Ordered passages inherit "fixed inputs downstream" for free.
7. **Structural simplification before numerics.** `SolveBySubstitution` unifies `a = b`; the
   solve-alone pass isolates single-unknown equations; tags partition unknowns into subsystems.
   Site/port equalities should be unified symbolically, not solved numerically.
8. **DOF and over-constraint from rank.** `dof = n - rank(J)`, `rankOk = rank == m`; results are
   `OKAY / REDUNDANT_OKAY / DIDNT_CONVERGE / REDUNDANT_DIDNT_CONVERGE`. Report exactly these four states
   per passage with DOF as a first-class number.
9. **Leave-one-out redundancy diagnosis with a time budget.** `FindWhichToRemoveToFixJacobian`
   yields "remove any one of these"; the unsatisfied set comes from residuals mapped through
   `hEquation::constraint()`. Both lists plus `solved.timeout` live on the group and are rendered.
10. **Per-param freeness.** `MarkParamsFree` drops one column at a time to flag underconstrained
    sites, drawn distinctly: the natural "which sites are still free" query for a lattice.
11. **Soft drag vs. hard lock.** Dragged params are weighted `1/20` in the minimum-norm step;
    `WHERE_DRAGGED` pins numerically. Interactive exploration should weight, not constrain, so DOF is unchanged.
12. **Charts as entities.** A workplane is a point + quaternion entity; 2D sites store `(u,v)` and
    lift via `NormalExprsU/V`; constraints carry a `workplane` and project. Sub-lattice charts and
    port frames fit the same coordinate-system-entity pattern.
13. **Measurement vs. constraint.** `reference` constraints generate no equations and are updated by
    `ModifyToSatisfy`; per-group policies (`allowRedundant`, `relaxConstraints`, `allDimsReference`,
    `suppressDofCalculation`) are persisted solver switches.
14. **Stable derived ids via a persisted remap.** `Group::Remap(input, copyNumber)` keeps constraints
    on derived geometry valid across regeneration; saved as `Group.remap={...}`.
15. **One schema table for persistence; the browser is a pure view.** `SAVED[]` drives save and
    load (unknown keys skipped); the text window is `Printf`-generated from state with link callbacks,
    and every diagnostic row (`ERR`, `%d DOF`, `remove any one of these`) links back into selection.
