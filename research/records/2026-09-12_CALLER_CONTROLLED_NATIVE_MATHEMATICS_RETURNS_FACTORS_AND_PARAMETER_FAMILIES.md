## Callable product

[established-bounded; implemented-exact; computational-witness] The public
`holonics::hna::native::NativeMathematicalSession` and existing `HnaStream` now accept supplied
mathematical problems. `holonics hna mathematical-session --input <JSONL or ->` exposes the same
owner. The request schema remains `org.holonics.hna.stream-request.v1`; the new action is
`mathematical-request`. Its typed operations construct linear/bilinear operators, continue a
finite support search, apply new inputs, bind or compose a receiver, read a retained product,
construct a calibrated condition relation, predict a full joint image, and refine the parameter
family from an actual observation. Explicit releases dispose of selected live objects.

[definition] `native/mathematical.rs` owns exterior exact codecs, application handles and
composition. `native/mathematical/relation.rs` moves the existing native relation and current
condition family; it supplies no replacement inference kernel. `stream.rs` owns JSONL delivery;
the workbench process binds it without collecting a batch or supplying mathematical answers.
No Athena/Hephaestus switch selects internal machinery.

## Recovered mathematics and executable correspondence

[proved-derived; formal-checked] The existing
`Mathematics/NavigatorFactorization.lean::bilinear_factorization` proves that a coefficient
certificate `T[o,i,j] = sum_r D[o,r] A[r,i] B[r,j]` realizes the entire bilinear action, over
an arbitrary finite commutative-ring chart. This implementation uses the already-established
exact `BilinearProductCore::bind` / `ExactRatMatrix::factor_receiver` to construct that
certificate. It adds no Lean invocation inside construction, development or inference.

[definition] The carried product is `p=(Ax) .* (Bz)` and the returned face is `Dp`. A new target
`T'` is available from that same product exactly when its requested linear tensor receiver
factors through the core's tensor image `K`. The binding returns the full family of `D'` with
`D'K=T'`, or a separator `Kv=0`, `T'v!=0`. The separator is a vector in the linear tensor carrier;
it is not falsely presented as necessarily a rank-one pair of physical inputs. Decoder free
row directions annihilate the full retained core; they are not uncertainty about the specified
target action. `ResidentBilinearMap` performs application and changed-receiver reads directly.

[definition] A requested linear action is lowered using its exact rank factorization and a
declared right unit port `[1]`. Its mathematical rank is reported separately from resident
carrier count: a zero map uses one zero packet lane because that existing primitive requires
nonempty matrices. Search reports first-found within the supplied forms and product range,
not global tensor-rank optimality. A candidate allowance yields a retained search frontier;
resumption does not restart the enumeration. A found candidate survives a mounting refusal.

[proved-derived] Native parameter inference uses the existing joint-image derivation from the
[September 7 family return](2026-09-07_AC1_CONDITION_FAMILIES_CONDUCT_AND_RETURN_THROUGH_THEIR_JOINT_FIBRE.md).
For supplied calibrated relation `R`, current condition family `H`, and source `x`, it constructs
`J_x = {(h,y) | h in H and (Phi(x,h),y) in R}`. Observation `y*` gives exactly
`H' = {h | (h,y*) in J_x}`. In affine coordinates
`J_x=(h0,y0)+span{(dh_j,dy_j)}`, the receiver imposes
`sum_j a_j dy_j = y*-y0` and returns `h0+sum_j a_j dh_j` with its full null directions.
The leading homogeneous coordinate pins the affine origin. This is executable equation
solving on the GPU, not a scalar state-change proxy for learning.

[definition] The native source chart is interleaved real/imaginary coordinates, with explicit
source, condition and complex mixed-product extents. Calibration rows are supplied action
