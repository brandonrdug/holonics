## Actual producer, not a caller-supplied mass cache

`receiving::selected::ProducedRetainedSection` is private to the receiving owners. Its constructor
runs the existing preflight and chronological retained scorer on the actual population, ring,
Faces, trees, target order and precision. It is never serialized, returned as a public handle,
kept across a native commit, or used in place of an actual producing Word.

`single_grain::ProducedFibreObservation` can only be constructed through the authenticating
`weights_at` owner. It keeps the same positive weight enclosures, normalizes them with the SAME
existing interval formula and summation order, and binds read/receiver/precision. It caches the
combined r(q,w), not a population mixture p. Every station still has its own chronological
population, ReceivingStep, target code and local population receive. The section return still
uses the actual shared INITIAL rho interval and one final whole-section beta.

At the initial64-bit precision the aligned return consumes those produced weights/masses and
already produced SelectedScored, rather than scoring the entire section again, normalizing each
station again and re-observing its weights. If a later precision is needed, it observes the SAME
original read through the existing authenticator. Source/receiver mismatch refuses. A private
section validates law/population/ring/Faces/tree/targets; a changed native invocation constructs
its own producer. No public SelectedScored or caller-injected enclosure can seed it.

The rational representative still takes midpoints of jointly produced positive WEIGHTS and then
normalizes them once. It is not a midpoint of rho or of normalized mass intervals. Exact packed
foil, component bounds/errors, norm and error pairing are unchanged. The ordinary certified V92
reference and the explicit uncached CODE branch retain their original scorer path and do not
allocate a producer cache merely to discard it.

Only the explicit LocalReceivingReturn scope selects this reuse. The executor's uncached CODE
control chooses computation reuse, not new material, target, law, precision or admission. Actual
forward/return/statistic dispatch and all physical/source guards are unchanged. The ordered R
then new-cut E interaction, blind carry, once-only ingress and pending/cold state retain the
sealed ordered reference's behavior.

The finite owner control compares complete SelectedScored, actual chronology, initialrho/finalbeta,
all returned foil/gradient/error/descent fields and fixed-key draws. A producer requested at32 bits
is compared to legacy score32 plus the legacy64-bit return ladder; complete returned values must
agree. Standalone original-source refinement to128 bits and changed source/context refusals are
also checked. Full native/cold/refusal and host/card controls are recorded separately.

Actual test counters cover score, normalized-mass, positive-weight, and `log2_enclosure_at` entry
calls for the measured sequential preparation. Counters are test-thread scoped and excluded from
native builds; another concurrent library test cannot pollute them. They do not infer hardware
kernels/transfers/synchronizations or root iterations. The existing Word owner counters remain
separate from this scalar preparation measurement.

and operation elimination. These are finite CODE measurements, not an end-to-end hardware or

This is ordinary producer-bound computation reuse. It is not learned structural compression,
