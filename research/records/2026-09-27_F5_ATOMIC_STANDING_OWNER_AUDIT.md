# F5 atomic standing owner audit

**Date:** 2026-09-27. **Scope:** the native checkpoint seam for the curated eight-family receiver in `hnn_population_curated.rs`; source-inspected only. This audit does not implement a codec, read private evaluation material, or pass the checkpoint gate.

## Objects and boundary

The computational object is the request/response **helical pair**: a request locates a receiver face and a response is the paired emanation read there, with its comparison pending until the declared receiving relation arrives. The six winding objects remain attached: **helix and pair** (the located relation and carried part clock), **cell holonomy** (no nontrivial holonomy is claimed), **faces and placement** (the family and population faces at their declared grain), **tube** (the source passage/cursor), and **tower thread** (tree restrictions and their standing). The existing implementation describes four at the population owner (helix, tube, faces/placement, tower thread); the pair and cell holonomy remain part of this product seam.

`Family::branch_future` is an ephemeral, read-only fork at the contemporary family standing used while preparing a prospective response. Its `Box<dyn Family>` is discarded after the probe. It is neither serialization nor a durable standing, and must not be persisted as another future or used to reconstruct state by replay. Durable retention is only the state sufficient for admitted future faces and receives. No occurrence tape, frozen producing cut, or replay fold is appropriate.

The exterior `athena_protocol.Checkpoint` is already an atomic, canonical single-file protocol carrying `standing: bytes`, cursor, pending comparisons, pending encoded output and sequence, and incomplete input tail. It fsyncs the file and directory around replacement. Its bytes are an opaque transport slot: `RefusingFixtureEngine` only inspects their length and refuses Ask. Thus the seam currently proves protocol-level output replay with opaque standing, not native standing restoration. A native transition must join its typed standing bytes, cursor, pending comparisons and output in that same commit. Keep an input frame unacknowledged until native use and checkpoint commit; once output is durable, replay its exact bytes under its sequence without another native call.

## Eight-family owner map

The curated constructor declares four cell-only `TreeFamily` instances at depths 6, 12, 24, 48, plus a fifth at the computed deepest admitted depth; two typed trees at depths 6 and 12; then one `AdmittedEgg`, whose embedded `BoundaryEgg` contains the deepest typed byte tree and depth-12 letter tree. There are eight population members total; the embedded trees are constituents, not ninth/tenth population members. All families have a common chart, population aperture, grain and naming description. Immutable declaration material (chart, depth, alphabet, population, grain, feature family, priors, capacity, selected hazard partition, copy law, incidence declarations and comparison partition declarations) can be reconstructed from a pinned manifest/configuration and its digest. It must be validated against the checkpoint before restoring dynamic fields.

## Continuation equation and validation

For each supported owner tag, define a canonical encoder `E` for contemporary constitution/standing `Θ` and a decoder `D`. The required identity is `D(E(Θ)) = Θ` (field equality after canonical normalization), and the operational consumer square is:

```text
face(D(E(Θ))) = face(Θ)
receive(D(E(Θ)), x) = receive(Θ, x)
E(receive(D(E(Θ)), x)) = E(receive(Θ, x))
```

The population square compares ordered family face vectors, exact posterior/enclosure operands, selected-family decision, relation receipts and the post-receive encoded standing. For end-to-end protocol runs, processing a complete input versus any split of that same frame with restart—including restart after the pending output is durable—must produce byte-identical checkpoint and output bytes. A typed format mismatch, unknown family tag, declaration digest mismatch, invalid arena index, malformed exact integer/rational, or inconsistent derived projection must refuse before accepting a frame. The checkpoint gate requires comparisons and pending output in this same file, not a sidecar.

## Public count and capacity evidence

F5's frozen receiver declaration has eight population members, `n* = 524288 = 2^19` cells, and depths 6/12/24/48, the computed deepest cell depth, typed depths 6/12 and embedded typed depth, plus letter depth 12. The development diagnostics report choosing preparation in 81,752–84,660 ms with sampled RSS about 6.7–7.1 GB; two simultaneous future branches in the one-request trial sampled 15,210,008,576 bytes, and the full request-only diagnostic sampled 14,652,568 KiB (sampled, not a captured peak). These measurements show branch memory is material and below the recorded 20 GB host limit, but they do not measure serialized native standing.

The public landmark capacity record reports 10,985,626 nodes and 1,371,879,880 occupied bytes for its distinct wide-cut benchmark. This is a useful order-of-magnitude warning (about 125 bytes per node in that benchmark), not a valid estimate for F5's eight-family state: the declaration and received cut differ. Therefore current evidence supports no concrete checkpoint byte prediction. Before implementation, instrument deterministic public counts after the 522,206 choosing cells: per family active nodes, stored chains/charts, hazard/copy/pointer map entries, live span bytes, and exact carrier byte widths. Compute encoded size from those counts and require it fit the declared host/device budgets; project peak encoder scratch and atomic replacement space (old plus candidate file). Do not infer a compression win from JSON or a node count alone.

## History lesson, blocker and implementation order

W1/W2 in [the workbench lessons](2026-09-24_LESSONS_FROM_THE_WORKBENCH_AND_ATHENA_PROTOTYPES.md) require output replay without repeating native work and byte-identical uninterrupted/split resume; the cursor is committed with the model, and input is acknowledged only after native use. D3 rejects archive retention: historical prototype paths kept reverse tapes, frozen producing cuts, return journals and a separate `.pairings.json`; the 4,436,880,359-byte checkpoint did not make that retention lawful. The old `cdd3c03e` save/session implementation belongs to retired history and is evidence only of a prior wire approach; do not restore its code or legacy decoders. The present protocol's same-file pending comparisons and pending output match W1/W2's delivery shape, while the native standing remains absent.

Implementation order, bounded to the exact missing join:

1. Freeze a declaration manifest for this eight-family configuration; define stable tagged native wire structs and a version with canonical exact integer/rational encoding.
2. Add state snapshot/restore APIs at owner boundaries: `Landmarks`/`Nodes`, `TreeFamily`, `BoundaryEgg`/`Hazard`/`LetterTree`, `AdmittedEgg` and finally `Population`/`Member`. Keep derived declarations rebuilt and verify their hashes/projections; retain only live admitted spans and remove them when their last relation is consumed.
3. Join native Ask transition with protocol's cursor, pending comparisons, encoded output/sequence, and input tail in a single candidate checkpoint commit; ensure an uncommitted native call cannot be acknowledged and durable pending output never triggers another native call.
4. Establish decode/face/next-receive squares per owner and full byte-identical continuation, then measure the public choosing standing's canonical byte size, encoder scratch and atomic replacement peak. Only this can close the checkpoint gate.

**Exact blocker:** there is no native `Population`/family/`Landmarks` serializer or typed restore owner; `athena_protocol` accepts only opaque standing bytes and its fixture engine has no release. Until the typed native payload restores the full current standing and its continuation squares pass inside the same atomic file as cursor and pending comparison/output state, F5 checkpoint acceptance is unpassed. The in-call crash window also remains open. This record does not claim that gate passed.
