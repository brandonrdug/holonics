## Purpose

This ledger decides every currently changed or untracked workspace path before corrective
construction begins.  `DELETE` means the hunk has no successor and must not be renamed as an
adapter.  `REBUILD` means preserve the named production owner and replace the rejected
implementation at that owner's typed mouth.  `KEEP/REGRADE` means the hunk belongs to an existing
owner but must be proven against the revised causal diagram.  `PRESERVE` applies only to ratified
records and operating contracts.  Generated PTX is never hand-edited; it is regenerated only from
the admitted device source.

No deletion in this ledger authorizes resetting an entire tracked file or overwriting unrelated
user work.  Every tracked change is handled by an exact `apply_patch` hunk.  The worktree is not a
rollback source.
