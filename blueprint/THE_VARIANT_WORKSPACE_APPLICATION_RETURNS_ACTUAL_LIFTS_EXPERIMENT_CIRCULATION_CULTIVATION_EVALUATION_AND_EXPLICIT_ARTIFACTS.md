## 2. Variant workspace and explicit artifacts

[definition] `VariantWorkspace` is an exterior application owner with one explicit absolute root.
The root is supplied on creation/open and is never derived from `HOME`, a global cache, a content
hash, or repository discovery. Paths are carriage and lineage, not morphology identity.

```text
ROOT/
  workspace.json
  lifts/lift-N/{cold-witness.json, insufficiency.json, lift-receipt.json}
  snapshots/generation-N.snapshot.json
  experiments/NAME.json
  runs/run-N/{run.json, boundary-N.json, candidate.json, commit.json, decline.json}
  evaluations/evaluation-N.json
  exports/export-N.{onnx,safetensors}
  receipts/artifact-N.json.
```

[definition] Every artifact reference in `workspace.json` is a normalized relative path which must
remain beneath the explicit root. Immutable artifacts use create-new semantics. The mutable
workspace manifest is replaced atomically by same-directory temporary write and rename only after
the new immutable artifacts validate. No overwrite check followed by an ordinary write is admitted.

[definition] `VariantWorkspaceManifest` returns schema, label, current snapshot, current generation,
derived `MorphologyVariantManifest`, lift testimony, experiment references, active run, completed
runs, evaluations, exports and open capabilities. It is the application chart, not native state.

## 4. World return and cultivation

[definition] `stage-return` receives explicit returned occurrence, boundary, exact complex current,
